01What is this?

A notebook, and your AI acting on it.

The AIOS is a free, open-source set of files that turns Claude Code, Anthropic's AI assistant that runs on your computer, into a personal assistant that remembers you. Most AI chats start from zero every time. The AIOS keeps a folder of plain-text notes about you, your work and how you like things done, and the assistant reads it at the start of every session. Over time it also writes down what it learns, so tomorrow's session knows what today's learned. An optional desktop app shows every session in a window you can watch.

A folder, not a service
Your computer
~/aios
Everything lives here, as plain-text files you can open and read. The AIOS has no server of its own and no telemetry.
INTENT.mdCLAUDE.mdUSER.mdvault/hooks/agents/
Your Claude account
Does the thinking. What a session reads is handled here, like any Claude chat.
Your private GitHub
A backup of every change, in your own account.
Tools you connect
Calendar, Gmail, Slack… one by one. Off until you connect them.
That is everything it talks to over the internet: your Claude account, GitHub (your backup and the update check), and only the tools you connect. Nothing runs in the background unless you add it.
You set how much it does alone

One file, INTENT.md, says what it does by itself, what it drafts for you, and what it always asks first.

New words?

The back cover explains ten of them in one sentence each. Not knowing them is the normal place to start.

This brief doesn't ask you to trust it. It shows you what to check, and where.

06Three layers, one owner

Anthropic's guardrails, the AIOS's own, and the app you see them through.

3 · The appwhat you see: every session in a visible window
2 · The AIOSwhat guides and records: contract, labels, git guards
1 · Claude Code + Claudethe hard floor: permissions, sandbox, the model’s judgment
Youset all three: what connects, what asks, what it may do alone.
Layer 1 · Anthropic

Claude Code + Claude

  • Asks before acting by default, until you add allow rules; review them in .claude/settings.json.
  • OS sandbox for shell commands: limits on writes and network. Reads need explicit denies.
  • Auto-mode review: risky actions, like launching an autonomous agent, can be refused.
  • Unattended runs launched the documented way get only the tools named for the job.
  • The model's judgment: trained to decline harmful requests; a control, not a guarantee.
Layer 2 · The AIOS

The framework's own

  • Trust contract per area, which says plainly that it guides rather than enforces.
  • Provenance labels on outside words.
  • Git guards: one commit path, secret scan, push guard.
  • 32 credential-leak checks run automatically on every change to the framework, plus one that checks connector versions stay locked.
  • Updates you can read and undo; anything to install asks for your consent.
  • A containment ladder, rung 0 to 5, with read-only probes that tell you where you stand.
Layer 3 · The app

Security as the interface

  • Sets Claude Code to ask first at setup, and never turns on its skip-permissions mode.
  • Every command runs in a visible terminal; the app never types into a session you can't see.
  • Agents coordinate through a folder: no listening port, nothing inbound.
  • A misspelled command is refused, not guessed; undelivered ones show up in your daily plan.
  • Sidebar boards render in a locked frame: no scripts, no network.
  • Signed and Apple-notarized; an update installs only if its signature verifies.
Layer 1 is the hard floor: rules a session cannot talk its way around. Layers 2 and 3 make the system visible and correctable. None of them replaces the choices in section 07.

07The levers you hold

Safety here is a set of choices you make.

The containment ladder, from the AIOS’s own guide
0What you already havedefault
1Know what leavesan hour · free
2Scope what an agent can touchan afternoon · free
3Separate the risky workper task
4A cheap always-on box~€5–10 / month
5The two-machine fortress~$600

Most of the real risk reduction is in rungs 1 and 2, and neither costs money. Know what leaves your machine; scope what an agent can touch. A second computer comes last.

1
Connect only what you need

A connection never made can't be talked into anything. Each agent can start with only the tools its task needs.

2
Set autonomy per area, and back it with rules

INTENT.md says what it does alone, drafts, or asks. For a hard stop, add a deny or ask rule in Claude Code's permissions.

3
Autonomy only on trusted sources

Autonomy is fine. Reading untrusted sources is manageable. The combination is the problem: unattended, nobody is there to say no.

4
Choose your model wisely

When a malicious document asks the AI to paste a password somewhere, the thing that refuses is the model. AIOS agents run on Claude by design; whatever you run in a terminal the app opens is your choice.

5
Separate reading from acting

Keep the identity that reads unknown content apart from the one that holds credentials. Use a bot with limited permissions when a bot is enough.

6
A separate browser profile

Log into only the sites you want an agent to reach. Never your bank. What it can't see, it can't use.

7
Decide how updates arrive

One line in USER.md turns automatic updates off. Before anything installs, you can always ask it to explain what it will do.

8
Climb the containment ladder in order

Rung 1: list what leaves. Rung 2: scope permissions, move keys out of your shell, install the git hooks. Only then a separate copy of the project, user account, server or second machine.

For a family or one person

Add one connection at a time, when a real task needs it.
Keep sending in draft. Emails and posts are prepared for you; you press send.
Keep money with a person. Set financial decisions to ask in INTENT.md, and don't log the agent's browser profile into your bank or shops.

For an IT department
Review-first updates on any machine with corporate credentials, ideally from an internal mirror pinned to a reviewed commit.
Bots with limited permissions, not personal accounts, wherever a bot is enough.
Sandbox read-denies for credential folders on unattended jobs.
Force-push protection on main in your git host, and the git hooks installed on each machine.
Vault backups to a company-owned repository, and the company's Claude plan.
Containment rungs as the baseline, not the advanced chapter.
Ask your AIOS, any time: “What will this update run?” · “What can the Slack connection actually do?” · “Which of my folders can a session read?” · “Which containment rung am I on?” (it runs read-only checks and shows the evidence). It answers from the code in front of it, not from a claim about it.

09Good to know

Its limits, and how you manage each one.

Every tool that acts for you has limits. These are the AIOS's, in plain words, and each one pairs with a lever in 07.

01Your Claude account is where the AIOS ends

The AIOS has no server. What a session reads is processed by your own Claude account at Anthropic, under the plan and privacy settings you chose there.

02Updates are automatic; installing asks you

Your daily plan keeps the AIOS current. When an update has something to install, it asks for your consent, and you can ask it to explain first. Updates aren't signed yet: they come from the public repository, where changes land by reviewed pull request.

03Three connectors don't lock their version

Google Workspace (the one that reads Gmail and Drive), Obsidian and Stitch fetch their latest version at launch, and disclose it before connecting.

04Agent requests are trusted by folder, not signature

Sessions leave each other requests in a folder on your machine that only you write to. Safe for one person; signed requests come before an inbox is ever shared.

05Your computer is the boundary

As with your browser or email app, credentials live on your disk, readable by programs running as you. That's true of most desktop software; rung 2 moves keys out of your shell, and the sandbox can deny credential folders.

06The app changes settings at setup

When you press the button, it edits Claude Code's settings (ask-first, your vault folder marked as trusted) and your shell startup files, and shows each command. It isn't App-Store sandboxed, on purpose: it must start real programs.

07INTENT.md guides; permissions enforce

The trust contract shapes what it chooses to do; Claude Code's permission rules are what can stop it. That's why trust is meant to grow from less to more: start with drafts and asks, and widen an area once it has earned it.

08Defaults favour what it can do

Restricting it is a deliberate choice of yours, made at your pace. A fair critique is that this is backwards; the containment ladder (section 07) is how you narrow it.

09No uninstall guide yet, but you can ask for one

Until it's written, ask Claude Code: “List everything the AIOS added to this machine and help me remove it, showing me each step before deleting anything.” Then revoke its access in your Google, Slack and GitHub accounts.

On a work machine

Back up the vault to a company-owned repository, not a personal one. Keep disk encryption on. Sign Claude Code into your company's Claude plan. Ask IT before connecting work Slack.

10Questions people ask

The questions IT will ask.

01Can it spend my money?

No payment tool comes with it. But the browser connector acts as you on any site you're logged into, so if the agent's profile is logged into a shop or bank, it could. Use a profile without them, set money to ask, and add a deny rule for a hard stop.

02Does Anthropic see my notes?

The parts a session reads are processed by your own Claude account, like any Claude conversation; that account and its privacy settings are between you and Anthropic. The AIOS has no server, no telemetry, and sends nothing anywhere else.

03What if it reads a malicious email?

It can carry instructions aimed at the AI, as it can for any AI assistant. Three things stand in the way: the provenance label, the model's training to refuse, and your permission rules (section 03). Fewer tools on the session that reads unknown mail narrows it further.

04What if I think it did something wrong?

Close the session. Every change is a git commit you can see and undo, and the transcript shows what it read and did. If an account may be affected, remove the AIOS's access there. Found a flaw? Report it privately (back cover).

05Can it send emails or messages as me?

If you connect Gmail or Slack, yes; Slack posts under your own name. INTENT.md can keep sending in draft, so you press send. For a hard limit, set those tools to ask in Claude Code's permissions.

06Can I turn it off, or uninstall it?

It runs only in sessions you open or schedule; nothing runs in the background unless you add it. Updates turn off with one line in USER.md. The pieces to remove: the ~/aios folder, its hooks in ~/.claude/settings.json, the marked blocks in your shell startup file, ~/.aios/, the credential folders, and the app. Revoke Google access from your Google account, or let Claude Code walk you through it (section 09).

07Who wrote it, and who reviews updates?

It's open source, published by The-AIOS on GitHub. Main is protected: changes land by reviewed pull request, and each passes 32 automated credential-leak checks. When an update has something to install, it asks for your consent first.

08Does it keep a record of what it did?

Yes, on your machine and in a private repository in your own GitHub account: every change is a git commit you can undo, the closing rituals write a daily note, and full session transcripts stay on your disk.

09Can it change things outside its folder?

It can run commands as you, within the permissions you set. When an update has something to install outside the folder, it asks for your consent and can explain it first.

10Should my company allow it?

A legitimate call either way. If yes: the IT checklist in section 08, and the containment ladder as the baseline. Ask a session “which containment rung am I on?” and it shows the evidence.

Ten words, one sentence each

Terminal: the text window where a computer runs commands.

Credentials: the logins and keys that let a tool act as you.

Connector (MCP): a plug that lets the AI use one service, like Gmail.

Hook: a small script that runs automatically at a fixed moment.

Vault: your folder of notes the AI reads and writes.

Git, commit, push: the record of changes; saving one; sending it to your private repository.

Sandbox: a fence that limits what a command can touch.

Permissions: the rules that say what runs, asks, or is refused.

Prompt injection: hidden instructions in content, aimed at the AI.

Agent bus: a folder where sessions leave requests for each other.
